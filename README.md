# CyberGuard – Cyber Incident Reporting & Case Tracking Website

College **Java OOP** mini-project. Browser → HTML/CSS/JS → Java Servlet/JSP → JDBC → MySQL, running on Apache Tomcat.
*Educational project – not a real or government cybercrime portal. Records marked DEMO are sample data.*

## 1. Requirements
| Tool | Version |
|------|---------|
| JDK | 17 or newer |
| Apache Maven | 3.8+ |
| MySQL | 8.x |
| **Apache Tomcat** | **10.1.x** (Jakarta namespace – Tomcat 9 will NOT work) |

Dependencies (JSTL, MySQL driver) are downloaded automatically by Maven – nothing to install by hand.

## 2. Create the database
```bash
mysql -u root -p < database/schema.sql
mysql -u root -p < database/sample_data.sql      # optional demo data
```
(`sample_data.sql` is generated by `python3 database/generate_sample_data.py`.)

## 3. Configure the connection (no credentials in code)
The app reads environment variables (or `-D` JVM properties):

| Variable | Default | Meaning |
|----------|---------|---------|
| `DB_HOST` / `DB_PORT` / `DB_NAME` | localhost / 3306 / cyberguard_db | MySQL location |
| `DB_USER` / `DB_PASSWORD` | root / *(empty)* | credentials |
| `DB_SSLMODE` | PREFERRED | use `REQUIRED` for cloud databases |
| `DB_URL` | – | full JDBC URL (overrides the four above) |
| `UPLOAD_DIR` | `~/cyberguard_uploads` | where evidence files are stored |

For local Tomcat create `TOMCAT/bin/setenv.sh` (Windows: `setenv.bat` with `set`):
```bash
export DB_USER=root
export DB_PASSWORD=your_mysql_password
```

## 4. Build and deploy on Tomcat
```bash
mvn clean package          # produces target/ROOT.war (also runs the unit tests)
cp target/ROOT.war $TOMCAT_HOME/webapps/
$TOMCAT_HOME/bin/startup.sh        # Windows: bin\startup.bat
```
Open <http://localhost:8080/> (the WAR is named `ROOT`, so there is no context path).
IDE option: import as a Maven project in Eclipse/IntelliJ and add a Tomcat 10.1 run configuration.

  ```sql

  ```
  Or create one with a hash from the helper: `java -cp target/classes com.cyberguard.util.PasswordUtil "MyStrongPass1"` and

## 6. Run and test
1. `/report` – submit an incident (login optional) → Case ID such as `CYB-2026-00011`.
2. `/track` – enter the Case ID → status timeline and public updates.
3. `/login` → dashboard, My Reports, Case Details.
4. `/admin-login` → dashboard (counts, search, category/status/date filters), assign, update status, add notes, resolve, close.
5. Full checklist: `docs/TEST_CASES.md`. Unit tests: `mvn test`.

## 7. Project structure
```
src/main/java/com/cyberguard/
  model/       User, Citizen, Staff, Investigator, Admin, Incident (abstract) + 5 subclasses,
               Evidence, Investigation, StatusHistory, CaseStatus (enum), interfaces
  dao/         UserDAO, IncidentDAO, EvidenceDAO, InvestigationDAO   (JDBC + PreparedStatement)
  service/     AuthService, IncidentService                          (business rules)
  controller/  Servlets, AuthFilter, SecurityHeadersFilter, listener (MVC controllers)
  util/        DBUtil, PasswordUtil, ValidationUtil, FileUtil, IncidentFactory, LoginThrottle
  exception/   AppException + 7 custom exceptions
src/main/webapp/ css/ js/ images/ WEB-INF/{web.xml, views/*.jsp}
database/        schema.sql, sample_data.sql, generate_sample_data.py
docs/            DIAGRAMS.md (architecture, class, ER), TEST_CASES.md, screenshots/
Dockerfile, deploy/   cloud deployment helpers
```

## 8. Where each OOP concept is used
| Concept | Example |
|---------|---------|
| Encapsulation | private fields + getters/setters in every model class |
| Inheritance | `User → Citizen / Staff → Investigator, Admin`; `Incident → 5 subclasses`; `AppException → 7 exceptions`; `BaseServlet` |
| Abstraction | abstract `User`, `Staff`, `Incident` (`getBaseRiskScore()`, `getCategoryGuidance()`) |
| Polymorphism | `IncidentFactory` returns the right subclass; `incident.assessPriority()` behaves differently per type |
| Interfaces | `PriorityAssessable`, `Trackable`, servlet `Filter` |
| Constructors | no-arg, partial and full constructors (overloaded) |
| Overloading / overriding | `lossScore()`/`lossScore(BigDecimal)`, `setStatus(CaseStatus)`/`setStatus(String)`, `requireText(...)`; `FraudIncident.assessPriority()` |
| Exception handling | checked `AppException` tree, try-with-resources, transactions with rollback |
| Collections | `List`, `EnumMap`, `LinkedHashMap`, `ConcurrentHashMap`, unmodifiable lists |

## 9. Security features
PBKDF2-HMAC-SHA256 salted password hashes · `PreparedStatement` everywhere · server-side validation · session auth with session-id rotation on login · role checks in `AuthFilter` · login throttling · upload whitelist + 5 MB limit + content-signature check + random file names + files stored outside the web root and always downloaded as attachments · CSP / X-Frame-Options / nosniff headers · output escaping with `<c:out>` · public tracking page shows no personal data and no internal notes.
Known limitations (good "future work" slide): no CSRF tokens (SameSite=Lax cookie only), no e-mail verification, sequential Case IDs, simple in-memory login throttle.

## 10. Hosting online (read this before using Netlify / Vercel)
**Netlify and Vercel cannot run this project** – they host static files and short serverless functions, not Tomcat, Java servlets or a MySQL database. Use a host that runs Docker containers plus a MySQL database:

1. Push this folder to GitHub.
2. Create a MySQL database at a provider that offers it (e.g. Aiven, Railway, TiDB Cloud, Clever Cloud – check current free plans) and run `schema.sql` (and optionally `sample_data.sql`) on it.
3. Create a **Web Service from a Dockerfile** (Render, Railway, Fly.io, Koyeb …) pointing at this repo. Set environment variables `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_SSLMODE=REQUIRED`.
4. Evidence files: container disks are usually erased on redeploy – attach a persistent disk mounted at `/data` (the Dockerfile already uses `UPLOAD_DIR=/data/uploads`) or accept that uploads are temporary for the demo.
5. **Domain:** buy a domain at any registrar, add it as a *Custom Domain* in your host's dashboard, then create the DNS record the host shows (normally `CNAME www → your-service.host.com`; for the bare domain an `ALIAS/ANAME` or `A` record). HTTPS certificates are issued automatically.
6. *Optional* – if you must keep the domain on Netlify/Vercel, deploy `deploy/netlify.toml` or `deploy/vercel.json` as a reverse proxy to your Java host (replace `YOUR-BACKEND-URL`). It adds latency and has upload size limits, so pointing the domain straight at the Java host is better.
